# Android redesign 2026-10 — binding rulings (R1–R12)

Source design: `docs/redesign/sroka-android.dc.html` (Claude Design export, HTML mock of 16 phone screens; render data
at the bottom in `renderVals()` lines 788–855). Read only the line range of your screens (table in R12).
These rulings override the mock where they conflict, and override `docs/DECISIONS.md` only where stated.
Progress is tracked in `docs/redesign/LEDGER.md`.

## R1 Scope
- Implement screens 01–16 (phone). **Screens 17–19 (foldables/tablet/tabletop/drag-drop) are out of scope**: keep the
  existing list–detail two-pane behaviour compiling and working, don't redesign or extend it.
- The yellow "New on Android"/"NEW" badges, the "M3 component / Custom" tags and the screen captions are annotations,
  never shipped UI.
- Use M3 components (`androidx.compose.material3`) wherever the mock names one (captions list them). Custom only
  where the mock marks "Custom component" (dashed tag): OTP input, download card, offline status card, resync card,
  match highlight, read-progress bar, reading progress line.

## R2 Theme (owned by task T1, `core/designsystem`)
- Brand palette always. **Dynamic color is dropped**: `SrokaTheme` ignores/loses the `dynamicColor` param default
  (keep the param for test call sites, default `false`, and `MainActivity` passes `false`); remove the Settings toggle
  (T5). Keep the `UserPreferences.dynamicColor` field (no migration churn), just unused.
- Dark scheme = the mock. Light scheme = same hues on the paper background (`#f6f5f1`), primary `#1e6f8f`.
  ThemeMode SYSTEM/LIGHT/DARK keeps working.
- Dark tokens (M3 role → hex):

  surfaceContainerLowest `#111317`, surfaceContainerLow `#1b1e23` (cards, sheets), surfaceContainer `#1f2228`
  (nav bar, menus, keyboard area), surfaceContainerHigh `#262a31` (search bar, dialogs), surfaceContainerHighest `#2f333b`
  (tonal chips, highlighted menu row), primary `#7cc0da`, onPrimary `#06323f`, primaryContainer `#1d3a47`,
  onPrimaryContainer `#9fd0e3`, secondary = primary family, tertiary `#f2c84b`, onTertiary `#15171c`,
  tertiaryContainer `#3a3220`, onTertiaryContainer `#f2c84b`, error `#f08f7f`, outline `#6b7079`,
  outlineVariant `#3a3f48`, inverseSurface `#f1efe9`, inverseOnSurface `#2a2e35`, inversePrimary `#1e6f8f`, scrim black.
- Extra brand colors not in M3 go in `SrokaExtendedColors` exposed as `MaterialTheme.srokaColors` (CompositionLocal,
  defined in `core/designsystem/.../theme/ExtendedColors.kt`):
  `brand` `#1e6f8f` / `onBrand` `#f6f5f1` (extended FAB, resync card, "Saved" check circle),
  `warning` `#e8cf86` / `warningContainer` `#2a2619` (offline card, partial save, pending "waiting" lines),

## R5 Navigation bar (T3)
- Order: My List (`bookmarks`), Favourites (`star`), Archive (`archive`), Tags (`label`). Selected = filled icon on
  primaryContainer indicator. The avatar (first letter of the signed-in email, primaryContainer circle) in the search
  bar / Tags app bar opens Settings. No separate settings icon on the list.

## R6 List rows & status lines (T0a data, T3 UI)
- Row: 56dp thumbnail (8dp corners; striped/letter placeholder when no thumbnail = first letter of domain on
  `#23272e`-ish surfaceContainerHigh), title 2 lines titleMedium, `domain · N min`, optional status line (12sp, 16dp
  filled icon), trailing filled yellow star when favourite.
- Status line priority: pending local change → warning colour `schedule` "Save waiting to sync" / "Tag change waiting" /
  "Favourite waiting" / "Change waiting to sync" (other) ; else parse PARTIAL → `warning` "Partial save" (warning colour);
  else DOWNLOADING/QUEUED → `downloading` "Downloading…" (primary); else DOWNLOADED → `offline_pin`
  "Available offline" (primary); else none.
- Swipe end-to-start archives (in Archive tab: moves back to My List — "Unarchive"), primary background with
  `archive` icon + label, snackbar "Archived" with Undo; when offline the text is "Archived. Syncs when you're online."

## R7 Cards above the list (T0a data, T3 UI)
- Exactly one card at a time, priority: Resync > Offline > Downloading; Idle shows nothing.
  - Downloading (`SyncPhase.Downloading`): surfaceContainerLow card, `download` icon, "Downloading for offline",
    "18 of 24", M3 `LinearProgressIndicator` (determinate). Collapses (AnimatedVisibility) when finished.
  - Offline (`SyncPhase.Offline`): warningContainer card, `cloud_off`, "Offline. N changes will sync later." (N =
    pendingOps; with 0: "Offline. Showing saved articles.").
  - Resync (new `SyncPhase.Resyncing(fraction: Float?)`, T0a): brand card, `sync`, "Catching up", percent, body copy
    from mock, yellow determinate progress (indeterminate if fraction null).
- Routine sync stays silent apart from M3 pull-to-refresh (`PullToRefreshBox`), which calls the existing manual
  sync/fetch trigger.

## R8 Search (T0a data, T3 UI)
- Tapping the search bar opens a full-screen search view (M3 `SearchBar` expanded / `ExpandedFullScreenSearchBar`
  or an equivalent full-screen layout). Filter chips: All / Archive / Favourites (All = every live item).
  Header "N results, searched on this phone". Result row: leading `article` icon (`archive` icon for archived
  items), title, `domain · Title and text|In title|In text|Archive · in text`, snippet with match highlighted
  (tertiaryContainer bg, onTertiaryContainer text). Works offline (local FTS only, as today).
- T0a adds `LibraryRepository.search(query: String, scope: SearchScope): Flow<PagingData<SearchResult>>` with
  `SearchScope {ALL, ARCHIVE, FAVORITES}` and `SearchResult(summary: ItemSummary, matchIn: MatchIn {TITLE, TEXT, BOTH},
  snippet: String?, highlights: List<IntRange>)` (model in `core/model`). Snippet via FTS4 `snippet()` on the
  `body` column (fallback excerpt) using private-use marker chars, parsed into ranges in core:data.

## R10 Reader (T5)
- Top app bar: back, spacer, star (favourite toggle, filled yellow when on), archive, overflow. Hides on scroll
  (enterAlways scroll behavior); 3dp yellow reading-progress line under it, always visible.
- Overflow menu order: Edit tags, Share link, Open in browser, Refresh article, Text size, divider, Delete (error
  colour). Refresh is disabled offline (`SyncPhase.Offline`).
- Refresh (already implemented as `LibraryRepository.refresh` → `item.refresh` op): while the item's parseStatus is
  PENDING after a user refresh, show an indeterminate `LinearProgressIndicator` under the app bar; when it settles
  show a snackbar: OK → "Article refreshed", PARTIAL → "Refreshed, still only part of the page", FAILED →
  "Couldn't refresh the article". Content reloads when the new package is downloaded.
- Header: site (primary, labelLarge), title (28/600), "11 min read · 42%", and for PARTIAL a warning-colour line with
  `warning` icon "Only part of this page was saved".
- When an article opens at a restored position > 2 %, snackbar "Continued from where you left off" with action
  "Start over" (scrolls to top and sets progress 0). (We don't know the other device, so no "on web".)
- Text size = existing reader text-size dialog.

## R11 Settings, import, export, account (T0b data, T6 UI)
- Settings rows per screen 13, sections Reading (Theme → single-choice dialog System/Light/Dark; Text size →
  single-choice dialog), Library (Offline downloads → existing policy dialog, sub "Wi-Fi only · 312 MB used";
  Server; Export library; Import), Account (Sign out, sub = email → plain two-button dialog; Delete account in error
  colour). Existing settings not in the mock (e.g. reader theme, sort order) stay, folded into the nearest section;
  only the dynamic-colour switch is removed (R2).
- Delete account dialog (screen 14): icon `delete_forever` (error), "Delete your account?", body from mock,
  outlined field "Type your email to confirm"; Delete enabled only when the trimmed input equals the account email
  case-insensitively. Replaces the current confirm.
- Import (screen 15), new screen `ImportKey`: intro copy, "Source" radios → server formats:
  Pocket → `pocket_csv` when the picked file is `.csv`/`.zip`, `pocket_html` when `.html`/`.htm`;
  Instapaper → `instapaper_csv`; Browser bookmarks (HTML) → `netscape_html`. **No "CSV or list of URLs" option**
  (server has no such format). File chosen with `ActivityResultContracts.OpenDocument`; outlined card shows file
  name + size ("Change"); filled "Import" button uploads. Then the progress card ("Importing…", "1,204 of 3,180",
  determinate when total known). Progress continues in a notification: a WorkManager worker in core:data polls
  `GET /v1/imports/:id` every ~3 s while running and posts a progress notification (channel "Imports", small icon
  `ic_stat_sroka`), final "Import finished: N links" / failure. Errors: 413 too large, 429 daily limit, 400 bad file,
  503 unavailable → typed errors → strings. Max file 20 MiB checked client-side first.
- Export (screen 16), new screen `ExportKey`: "Format" radios **CSV and JSON only** (server `GET /v1/exports?format=csv|json`;
  no HTML, and **no "Include" switches** — the server always exports all live items). Subtitles: CSV "Links, tags and
  dates in a spreadsheet", JSON "Everything Sroka knows about each link". Filled "Export" builds it (download to
  `cacheDir/exports/`, filename from Content-Disposition), then the ready card: `check_circle`, file name,
  "Ready · 48 KB · N articles" (count if cheaply known, else just size), outlined "Share" (FileProvider +
  ACTION_SEND) and filled "Save" (`ActivityResultContracts.CreateDocument`, copy the file).
- T0b API/domain: `SrokaApi.createImport(file: File|stream, fileName, format): ApiResult<JobDto>`,
  `getImport(id)`, `export(format, dest: File): ApiResult<ExportFile>`; domain `DataTransferRepository`
  (core/domain) with `startImport(uri: String, format: ImportFormat): ImportStartResult`, `observeImport(jobId): Flow<ImportJob?>`
  / `activeImport(): Flow<ImportJob?>` (last started job id persisted so the screen survives process death),
  `export(format: ExportFormat): ExportResult`. This repository may call the network directly (an explicit
  exception to the "network only in SyncEngine/ContentStore" convention: imports/exports are online-only). Models `ImportFormat`, `ExportFormat`, `ImportJob`, `JobStatus`
  in core/model. Fake in core/testing. Auth header like every other `/v1` call.
