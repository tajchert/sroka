# @sroka/extension — WXT MV3 Chrome extension

Popup (sign-in email → 6-box code, saving → success → saved with tags/favourite/remove/open, tag editor, removed, queued/failed), context menus (save link/page; right-click the toolbar icon → "Open Sroka" opens `${appOrigin}/app/` in a new tab via `lib/open-app.ts`; while the active tab's page is saved it also shows "Open in Sroka" (`/app/item/:id`) and "Remove from Sroka" — visibility synced in `paintBadge`/`syncItemMenu` (`lib/badge.ts`), handlers in `lib/item-menu.ts`), per-tab badge, retry queue, options page.

## Commands
- `npm run dev -w @sroka/extension` · `npm run build -w @sroka/extension` → `.output/chrome-mv3` · `npm run zip -w @sroka/extension`
- Manifest `key` pins the unpacked id to `gmfnkkciofcaafddbcgphofiikmplema` (= API `EXT_ID`); `zip` sets `SROKA_STORE_BUILD=1` to omit it (Web Store rejects `key`), then rebuilds `.output/chrome-mv3` with the key: a keyless unpacked build gets another id, which the API rejects ("Invalid origin").
- `npm run typecheck -w @sroka/extension` (runs `wxt prepare` first) · `npm test -w @sroka/extension`

## Key files
- Popup implements Claude Design "Sroka Popup"/"Sroka Extension" (dark only, 340px): `entrypoints/popup/App.tsx` + `assets/popup.css`. Options page uses `assets/tailwind.css` (light/dark). Brand mark + glyph in `components/Mark.tsx`.
- `wxt.config.ts` (manifest, permissions, dev host permission for localhost:8787), `entrypoints/background.ts`, `entrypoints/popup/*`, `entrypoints/options/*`, `assets/tailwind.css`.

## Decisions that apply
D8 (features, server URL option default `https://api.sroka.app`; when the user saves a custom URL the options page must call `chrome.permissions.request({ origins: [new URL(url).origin + "/*"] })` — allowed by `optional_host_permissions` — and refuse to save if denied; "Open library" opens `${appOrigin}/app/` from `GET /v1/config`), D4 (bearer token from `set-auth-token` header, `chrome.storage.local`), D1.
Capture: `saveTab` sends the rendered `html` when the "always capture" option is on (default **on**), and always when `detectPaywall` matches or `alwaysCapture(url)` (Reddit), both from `@sroka/shared`. `pageHtmlForCapture` runs in the page and strips scripts (except JSON-LD), styles, stylesheet/preload links, SVG and templates; on a Reddit thread it is async and appends the pruned thread `.json` as `script#sroka-reddit-json` (D13; test `lib/capture.test.ts`, jsdom). `saveItem` gzips the body (`Content-Encoding: gzip`) when it carries `html`. Tests read request bodies with `requestJson` (`lib/test-chrome.ts`).
Telemetry (D15): `lib/consent.ts` (`sroka.consent.v1` in storage.local; analytics opt-in, errors default on; revoking analytics deletes the client id), `lib/analytics.ts` (GA4 Measurement Protocol sent only from the background via `no-cors` fetch, so **no host permission for google-analytics.com**; popup/options call `track()` which messages the background), `lib/error-reporting.ts` (`POST {server}/v1/client-errors`, `release: "ext-<version>"`, page path only). Config `analytics.config.json` (gitignored; example committed) is read in `wxt.config.ts` into the `__SROKA_GA__` define; absent → no consent prompt/switch, nothing sent. Tests stub `__SROKA_GA__` with `vi.stubGlobal`.

## Chrome Web Store privacy tab (must declare)
- Data collected: anonymous usage analytics (feature-use events, no content/URLs; opt-in, off until accepted) sent to Google Analytics (third party); error reports (message, stack, extension page path, user agent, extension version; opt-out) sent to our own server. Not sold, not used for ads; no personalized ads. Privacy policy `https://sroka.app/privacy`. Remote code: none.
- Releases built without `analytics.config.json` have no analytics at all; the store build needs it present.

Badge privacy (D8, 2026-11-10): the badge never sends the visited URL. `lib/saved-set.ts` keeps 12-hex-char sha256 prefixes of `normalizeUrl(url|canonicalUrl)` of saved items in storage.local (256 shards `savedSet.<xx>` = `{hash: id without dashes}` + `savedSet.meta` {owner, cursor}), filled by `GET /v1/sync/pull` (full pass with `full=1` first or after 410, then incremental; tombstones remove), refreshed on install/startup, token change (sign-in), alarm `sroka-saved-set` (20 min); `addSaved`/`removeSaved` on the extension's own saves/deletes; `clearSavedSet` in `clearSession`. Not loaded → no badge. `lookupUrl` (`GET /v1/items?url=`) only after a user action (toolbar menu). The `tabs` permission is still needed to read tab URLs for the local lookup.
Retry queue bounds (`lib/queue.ts`): a retryable save is dropped only when older than 7 days *and* tried ≥10 times; entries waiting for sign-in never expire; at 500 entries new saves are refused (`QueueFullError`, shown as a failed save). Every drop goes to `failedSaves`, which the popup shows (`FailedSavesCard`, Dismiss clears it).
API: `POST /v1/items` (with `html` when capturing), `GET /v1/sync/pull` for the badge set, `GET /v1/items?url=` for the toolbar menu fallback, `GET /v1/tags/suggestions?url=`, `PATCH /v1/items/:id {tags}`. See `docs/api.md` and research/ext.md gotchas. Don't add deps.
