# @sroka/extension — WXT MV3 Chrome extension

Popup (sign-in email → 6-box code, saving → saved (one screen, crossfade; header "Saved"/"Already saved", tags row, one row with Favorite toggle + "Open", Remove in the header "⋯" menu; closes itself after 3 s, see below), tag editor, removed, queued/failed), context menus (save link/page; right-click the toolbar icon → "Open Sroka" opens `${appOrigin}/app/` in a new tab via `lib/open-app.ts`; while the active tab's page is saved it also shows "Open in Sroka" (`/app/item/:id`) and "Remove from Sroka" — visibility synced in `paintBadge`/`syncItemMenu` (`lib/badge.ts`), handlers in `lib/item-menu.ts`), per-tab badge, retry queue, options page.

## Commands
- `npm run dev -w @sroka/extension` · `npm run build -w @sroka/extension` → `.output/chrome-mv3` · `npm run zip -w @sroka/extension`
- Manifest `key` pins the unpacked id to `gmfnkkciofcaafddbcgphofiikmplema` (API `EXT_ID` trusts it and the Web Store id `mgeodllnkiehnjbdogljfjgdbadjdblh`); `zip` sets `SROKA_STORE_BUILD=1` to omit it (Web Store rejects `key`), then rebuilds `.output/chrome-mv3` with the key: a keyless unpacked build gets another id, which the API rejects ("Invalid origin").
- `npm run typecheck -w @sroka/extension` (runs `wxt prepare` first) · `npm test -w @sroka/extension`

## Key files
- Popup implements Claude Design "Sroka Popup"/"Sroka Extension" (340px; light by default, dark under `prefers-color-scheme: dark`, tokens at the top of the CSS): `entrypoints/popup/App.tsx` + `assets/popup.css`. Options page uses `assets/tailwind.css` (light/dark). Brand mark + glyph in `components/Mark.tsx`.
- `wxt.config.ts` (manifest, permissions, dev host permission for localhost:8787), `entrypoints/background.ts`, `entrypoints/popup/*`, `entrypoints/options/*`, `assets/tailwind.css`.

Re-save with extension (web reader "Preview only" banner → `lib/resave.ts`, wired in `entrypoints/background.ts`):
- Channel: manifest `externally_connectable.matches` = `https://sroka.app/*` (+ `http://localhost/*`, any port, in non-store builds; `SROKA_STORE_BUILD` drops it). No permission warning, no host permission, no content script. `chrome.runtime.onMessageExternal` re-checks `sender.origin` (fallback `sender.url`) against the manifest's own `matches`.
- Messages: `{type:"sroka.ping"}` → `{ok:true, version}`; `{type:"sroka.resave", itemId: uuid, url: http(s)}` → `{ok:true, opened:true, auto}` | `{ok:false, error: "bad_origin"|"bad_request"|"not_in_library"|"signed_out"|"offline"|"error"}`. `resave` must come from a tab; the extension fetches `GET /v1/items/:id` with its own token (404 / other account → `not_in_library`), requires the sent URL to match the item's url/canonicalUrl (`pageKey`: host without `www.`, path without trailing slash, normalized query), opens the **item's** URL next to the web tab and remembers that tab id in storage.session `sroka.resave.v1` (10 min TTL, dropped on tab close).
- Only that tab is ever re-saved, once it shows the item's page (a login redirect keeps it pending), always with forced capture (`saveTab(tab, {forceCapture:true})`: html whatever the setting; no save if capture fails) under the item's URL, so the API's html-save path force re-parses the existing item (api.md §5.1). Capturing needs `activeTab` or a host permission, and a web message grants neither: with host access already granted (`permissions.contains`, e.g. optional `https://*/*`) it saves by itself after load + 1.5 s (`auto:true`); otherwise (`auto:false`, the usual case) the tab's badge shows `↻` + title "Click to save the full page to Sroka" (also kept by `refreshBadge`) and the user's next popup/shortcut/"Save page" in that tab claims it (`takeResave`) and saves with forced capture. Logs carry no URLs.
- The web side keeps the extension ids in `apps/web/src/lib/extension.ts` `EXTENSION_IDS` (Web Store `mgeodllnkiehnjbdogljfjgdbadjdblh`, dev/unpacked `gmfnkkciofcaafddbcgphofiikmplema`).

Sign-in click (`openedSignedOut` in `entrypoints/popup/App.tsx`): a popup opened while signed out never saves or queues the page (and never calls `takeResave`); after sign-in it shows a "You're signed in / click the Sroka icon on any page to save it" screen (phase `welcome`, no auto-close, as auto-close is saved-only) and the next icon click saves. A popup opened signed in whose token turned out expired still saves the page after re-login.

Analytics consent card (D15): not shown at first run or on sign-in. `sroka.hasSaved.v1` (storage.local) is set on the first successful save from any path (`saveWithFallback`, queue flush); the popup asks `consentCardDue()` together with the saved result and renders the card only on the saved screen (`consentCardVisible`) while the answer is unanswered (unanswered = nothing sent). The 3 s auto-close is held while it shows (`autoCloseWanted`). Options page switches unchanged.

Saved-popup behaviour: `lib/auto-close.ts` (pure timer: `start`/`hold`/`release`/`cancel`, vitest with fake timers) closes the popup 3 s after the saved state shows (new or already saved). Hover or keyboard focus pauses it; any click/keypress cancels it for good until the next save; it never runs in any other phase nor while the consent or failed-saves card shows; reduced-motion hides the shrinking line but still closes. Manifest `commands._execute_action` (suggested Ctrl+Shift+S, Mac Command+Shift+S; not Alt+Shift+letter, which blocks Polish Ś/Ą; not Ctrl/Command+Shift+Y, which Bitwarden uses) opens the popup; `lib/shortcut.ts` reads the real binding via `chrome.commands.getAll()` and the popup shows it once (`sroka.shortcutHint.v1`), only if bound. Options page "Keyboard shortcut" shows the binding (or Off, re-read on focus) and opens `chrome://extensions/shortcuts` (`openShortcutSettings`): an extension cannot change or clear its own binding, so turning it off means clearing it there. Failed-save wording lives in `lib/save-failure.ts` (body never repeats the title). US spelling "Favorite" everywhere.

## Decisions that apply
D8 (features, server URL option default `https://api.sroka.app`; when the user saves a custom URL the options page must call `chrome.permissions.request({ origins: [new URL(url).origin + "/*"] })` — allowed by `optional_host_permissions` — and refuse to save if denied; "Open library" opens `${appOrigin}/app/` from `GET /v1/config`), D4 (bearer token from `set-auth-token` header, `chrome.storage.local`), D1.
Capture: `saveTab` sends the rendered `html` when the "always capture" option is on (default **on**), and always when `detectPaywall` matches or `alwaysCapture(url)` (Reddit), both from `@sroka/shared`. `pageHtmlForCapture` runs in the page and strips scripts (except JSON-LD), styles, stylesheet/preload links, SVG and templates; on a Reddit thread it is async and appends the pruned thread `.json` as `script#sroka-reddit-json` (D13; test `lib/capture.test.ts`, jsdom). `saveItem` gzips the body (`Content-Encoding: gzip`) when it carries `html`. Tests read request bodies with `requestJson` (`lib/test-chrome.ts`).
Telemetry (D15): `lib/consent.ts` (`sroka.consent.v1` in storage.local; analytics opt-in, errors default on; revoking analytics deletes the client id), `lib/analytics.ts` (GA4 Measurement Protocol sent only from the background via `no-cors` fetch, so **no host permission for google-analytics.com**; popup/options call `track()` which messages the background), `lib/error-reporting.ts` (`POST {server}/v1/client-errors`, `release: "ext-<version>"`, page path only). Config `analytics.config.json` (gitignored; example committed) is read in `wxt.config.ts` into the `__SROKA_GA__` define; absent → no consent prompt/switch, nothing sent. Tests stub `__SROKA_GA__` with `vi.stubGlobal`.

## Chrome Web Store privacy tab (must declare)
- Data collected: anonymous usage analytics (feature-use events, no content/URLs; opt-in, off until accepted) sent to Google Analytics (third party); error reports (message, stack, extension page path, user agent, extension version; opt-out) sent to our own server. Not sold, not used for ads; no personalized ads. Privacy policy `https://sroka.app/privacy`. Remote code: none.
- Releases built without `analytics.config.json` have no analytics at all; the store build needs it present.

Badge privacy (D8, 2026-11-10): the badge never sends the visited URL. `lib/saved-set.ts` keeps 12-hex-char sha256 prefixes of `normalizeUrl(url|canonicalUrl)` of saved items in storage.local (256 shards `savedSet.<xx>` = `{hash: id without dashes}` + `savedSet.meta` {owner, cursor}), filled by `GET /v1/sync/pull` (full pass with `full=1` first or after 410, then incremental; tombstones remove), refreshed on install/startup, token change (sign-in), alarm `sroka-saved-set` (20 min); `addSaved`/`removeSaved` on the extension's own saves/deletes; `clearSavedSet` in `clearSession`. Not loaded → no badge. `lookupUrl` (`GET /v1/items?url=`) only after a user action (toolbar menu). The `tabs` permission is still needed to read tab URLs for the local lookup.
Retry queue bounds (`lib/queue.ts`): a retryable save is dropped only when older than 7 days *and* tried ≥10 times; entries waiting for sign-in never expire; at 500 entries new saves are refused (`QueueFullError`, shown as a failed save). Every drop goes to `failedSaves`, which the popup shows (`FailedSavesCard`, Dismiss clears it).
API: `POST /v1/items` (with `html` when capturing), `GET /v1/sync/pull` for the badge set, `GET /v1/items?url=` for the toolbar menu fallback, `GET /v1/tags/suggestions?url=`, `PATCH /v1/items/:id {tags}`. See `docs/api.md` and research/ext.md gotchas. Don't add deps.
