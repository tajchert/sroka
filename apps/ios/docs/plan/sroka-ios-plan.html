Not in scope (Android does not have them either)

Server contract

A native client is not specially registered anywhere. Android is admitted because it sends a bearer token and no Origin header; iOS works the same way from day one.

Hosts

  • https://api.sroka.app: auth and /v1, bearer token. This is the app's default server.
  • https://c.sroka.app: signed content URLs only. Send no auth header there.
  • Local: npm run dev:setup once, then npm run dev -w @sroka/api serves everything on http://localhost:8787. The Simulator reaches the Mac's localhost directly. Sign-in codes are printed in the wrangler log as [sroka] OTP for <email>: <code>.

Headers on every API call

  • Authorization: Bearer <token>
  • X-Sroka-Device: ios_<uuidv7>, generated once per install and kept across sign-out. It is the idempotency and tie-break identity.
  • User-Agent: Sroka-iOS/<version>

Rules that bite

  • Never send an Origin header. A request with Origin: https://sroka.app is treated as the web app and fails with 400 TURNSTILE_FAILED (workers/api/src/turnstile.ts). URLSession sends none; do not call the API from inside WKWebView.
  • The session token arrives in the set-auth-token response header of the sign-in call. Store it verbatim; it contains . and may contain =.
  • Sessions last 90 days, rolling. A 401 means "ask the user to sign in again", never "wipe data" (D4).
  • Two error shapes: /v1 returns {error, message?}; Better Auth returns {code, message}. Auth rate limits use the header X-Retry-After, /v1 uses Retry-After. Parse both.
  • Decode every enum-like field as a string with an unknown fallback. The server already returns codes that are missing from the shared enum (length_required, storage_full).

iOS specifics

  • Two processes share the file. Follow GRDB's guide for App Group databases: WAL mode with a persistent WAL, NSFileCoordinator only around creation and migration, and observesSuspensionNotification so the app is not killed with exception 0xDEAD10CC for holding a lock while suspended. The extension opens the pool only after migrations are known to be current, otherwise it shows "Open Sroka to finish updating".
  • Migrations are never destructive. When a release starts reading a new server field, the migration also sets sync_state.cursor = 0 so every row is pulled again. Android needed two migrations to get this right.
  • Search query. Each run of letters or digits becomes a quoted prefix term in FTS5 form "term"*, joined with AND; at most 8 terms of 64 characters. Android writes "term*" because it is on FTS4. FTS5 has no offsets(); derive "In title / In text" from a column filter ({title}: …) or from highlight() on the title column.
  • List queries use ValueObservation with keyset paging. Port the query-plan test (ListPlanTest on Android) that asserts the sort indexes are used.

Sync engine

The largest piece of logic and the one where a faithful port matters most. One actor, single-flight, shared with the local wipe so the two never interleave.

Reference: apps/android/core/data/…/sync/SyncEngine.kt, …/ops/OpWriter.kt, …/ops/LocalOpApplier.kt, …/ops/WireOp.kt, ruling A8, and docs/api.md §7–8. Server-side rules: packages/shared/src/ops.ts, lww.ts, hlc.ts.

Writes

Every user action is one database transaction: apply the change to the local rows and the FTS row, insert a pending_ops row, then request a sync debounced by 2 s. Ten op types exist: item.add, item.setStatus, item.setFavorite, item.setProgress, item.tag, item.setTitle, item.delete, item.refresh, tag.rename, tag.delete. Each carries a UUIDv7 opId and at from OpClock (max(now, last + 1), strictly increasing per device). On enqueue, older unsent ops of the same item and type are deleted for setProgress, setStatus, setFavorite and setTitle only.

One sync pass

  1. Push in batches of up to 500 ordered by local_seq. In one transaction: delete applied and rejected ops; for a rejection item_deleted where an item.add is still queued, re-key the item to a fresh UUIDv7 with fresh op ids and keep the ops (the user re-saved a URL the server had tombstoned); for other item_deleted, delete the item, its ops and its files; for each aliases[clientId] = existingId, re-target queued ops and merge or re-key the local row.
  2. If the cursor is 0, mark the pass as a full resync so every pull page sends full=1.
  3. Pull pages of 500 until hasMore is false. Each page is one transaction: upsert items and replace their tags, apply deleted.items and deleted.tags, then rebase: re-apply still-queued ops for the touched items and all tag-level ops through LocalOpApplier, so unsent local changes stay visible. Save the cursor. Delete files of removed items after commit.
  4. On 410 resync_required (once per pass): mark every item, set the cursor to 0, push again, pull from 0 with full=1, then delete items still marked that have no pending ops.
  5. After success: queue automatic downloads by policy and run eviction.

Outcomes

  • 401: mark the session expired, keep all data, stop. Network failure: silent, retry later. Anything else: record http_N on the ops and retry with exponential backoff from 30 s, at most 5 attempts per trigger. The engine itself does not loop; on Android WorkManager retries, on iOS the scheduler must.
  • Status shown in the list, one card at a time, by priority: session expired, resyncing, offline (with the count of queued changes), downloading.

Triggers on iOS

  • Scene becomes active; any local write (2 s debounce); pull to refresh; Refresh polling in the reader; PDF upload or import finished.
  • BGAppRefreshTask stands in for Android's hourly job. iOS decides when it runs, so never rely on it for correctness.
  • The Share Extension does one push with a short timeout after its write (see below).
Keep payload JSON canonical. Alias and re-key handling on Android rewrite "itemId":"…" inside stored payloads by string replacement, which only works because the JSON is compact. In Swift, either store payloads with a fixed encoder configuration and re-encode on rewrite, or keep the op fields as columns. Do not copy the string replace.

Offline content

An article is a zip per content version. Download, verify, unpack atomically, index the text.

Reference: apps/android/core/data/…/content/ContentStoreImpl.kt, PackageInstaller.kt, HtmlText.kt, …/sync/ContentDownloadWorker.kt, ruling A9, docs/api.md §10.

  1. Eligible: has a content_id, is unread or favorite, and its content_files row is missing, stale, queued, or failed fewer than 5 times. Newest first, 3 at a time.
  2. GET /v1/items/{id}/content. 409 means not parsed yet (not an attempt). Require 100 MiB free, otherwise stop the batch with "device storage is full" (also not an attempt).
  3. Download packageUrl with no auth header; abort above 50 MiB.
  4. Install safely: reject absolute paths, .., \, :, NUL, names over 512 characters and case-insensitive duplicates; at most 200 entries and 50 MiB unpacked; manifest.json must list article.html; verify every file's SHA-256; unpack into articles/{id}.tmp and swap into place by rename.
  5. Extract plain text from article.html (drop script, style, head, template, noscript and comments; strip tags; decode entities; cap at 300,000 characters) into the FTS body.
  6. Commit the row as downloaded in one transaction that re-checks the item still exists and that "Remove downloaded articles" did not run meanwhile.
  7. If lead_image_key is set, fetch baseUrl/key (up to 5 MiB) to thumbs/{id}.webp; retried separately, 3 attempts. iOS decodes WebP natively.
  • PDF items: fetch documentUrl (up to 50 MiB), check %PDF- in the first kilobyte, store as articles/{id}/document.pdf. If the signed URL answers 401, 403, 404 or 410, fetch fresh URLs once.
  • Layout in the App Group container: articles/{id}/, thumbs/{id}.webp, pdf-uploads/, with isExcludedFromBackup set on all three. Item ids become file names and reader URLs, so validate them against ^[A-Za-z0-9_-]{1,64}$.
  • Policy: Wi-Fi only maps to allowsExpensiveNetworkAccess = false on the session configuration; Any network is the default configuration; Manual queues nothing automatically. A user-initiated Fetch ignores Wi-Fi only, as on Android.
  • Eviction after each successful sync: archived, non-favorite items archived more than 30 days ago that were neither downloaded nor read in the last 30 days. The FTS body is kept.
  • Recovery once per launch: rows stuck in "downloading" go back to queued; rows marked downloaded whose files are missing are dropped.

Reader

Same HTML wrapper, same CSS variables, same progress model as Android and the web, so an article looks and resumes identically on every device.

Reference: apps/android/feature/reader/impl/…/ReaderHtml.kt (wrapper, theme CSS, post-card CSS, reader script), …/ui/ArticleWebView.kt, …/ReaderViewModel.kt, …/ReaderReasons.kt, …/ui/EndOfArticleCard.kt, ruling A10. Web copy of the same CSS: apps/web/src/lib/reader.ts.

  • Loading. Register a WKURLSchemeHandler for sroka-article://{itemId}/ that serves files from articles/{itemId}/ and nothing else. Load the wrapped HTML with that base URL so relative img/… paths resolve. This replaces Android's WebViewAssetLoader.
  • Lock it down. A WKContentRuleList that blocks every http and https load; allowsContentJavaScript = false for page content; the reader script injected as a WKUserScript in its own WKContentWorld, with the progress WKScriptMessageHandler registered only in that world. Article HTML is already sanitised server-side; this keeps the second line of defence that Android has.
  • Links. Cancel navigation in decidePolicyFor; open http(s) targets in SFSafariViewController; ignore every other scheme.
  • Appearance. Theme Auto / Light / Sepia / Dark, font Sans / Serif, scale 0.8 to 1.6 in 9 steps over an 18 px base, spacing 1.45 / 1.65 / 1.9, column capped at 42 em. Apply changes by updating CSS variables through evaluateJavaScript, without a reload. Font stacks on iOS: system-ui (San Francisco) and ui-serif (New York). Dark theme dims images as on Android.
  • Progress. progress = scrollTop / (scrollHeight − clientHeight), clamped to 0…1. anchor is the index of the first element at or below the viewport top among p,h1,h2,h3,h4,h5,h6,li,blockquote,pre,figure (PROGRESS_ANCHOR_SELECTOR in packages/shared/src/limits.ts). Report every 150 ms while scrolling; write locally at most every 2 s, 1 s after scrolling stops, and on leave. Restore by anchor, falling back to progress. Opening an article updates last_read_at and so queues one item.setProgress even without scrolling. Above 2% show "Resumed at N%" with "Start over".
  • States. Downloading; "Not saved for offline reading"; "Preparing article"; "Couldn't save the text" with a plain reason and "Try again" / "Open original"; web content process terminated (webViewWebContentProcessDidTerminate). Reason strings come from packages/shared/src/vocab.ts failureReason(); never show the raw code.
  • Keep awake while reading with isIdleTimerDisabled, released after 5 minutes without interaction.
  • Posts and threads. X posts and Reddit / Hacker News threads arrive as sr-* classes (D11, D13). Copy POST_CARD_CSS unchanged.
  • PDF. PDFView, continuous vertical. Progress is (page + 1) / pageCount with the page index as anchor, written on each page change.

Share Extension and the save path

The most iOS-specific part: a separate process with about 120 MB of memory and a few seconds of life.

Reference for behaviour: apps/android/feature/library/impl/…/save/SaveSheetViewModel.kt, SaveSheetHost.kt, and UrlNormalizer.extractFirstUrl in apps/android/core/model/…/UrlNormalizer.kt.

  1. Activation rule accepts web URLs, plain text and PDF files. Take the URL attachment first, then the first http(s) URL found in shared text (trailing punctuation and unbalanced closing brackets stripped). No URL shows "No link found in what you shared".
  2. Read the token from the shared Keychain group. Signed out shows "Sign in to Sroka to save articles".
  3. Normalise the URL, look up canonical_url. A new item gets a UUIDv7 id, parse_status = pending, saved_at = now; an existing one is moved back to My List. Queue item.add with onDuplicate: "readd". One transaction. This works offline.
  4. Show the sheet at once: "Saved" (or "Already saved" with reading progress), the item card, Tags, Favorite, Open. It dismisses itself after 4 s unless touched.
  5. Fire one POST /v1/sync/push with a short timeout. If it fails, the app pushes on its next activation.
  6. PDF: copy the file into pdf-uploads/ in the container and hand the upload to a background URLSession with the shared container identifier, then show "Adding PDF to Sroka".
  • Link only SrokaCore, SrokaDatabase and a minimal push client into the extension. No reader, no Firebase, no download code.
  • "Open" uses a private URL scheme (sroka://item/{id}) handled by the app, the counterpart of Android's EXTRA_OPEN_ITEM_ID.
  • After the app returns to the foreground it must re-read state the extension may have changed; database observation covers the list, and the sync trigger on activation covers the push.

Session, sign-out and account deletion

Reference: apps/android/core/datastore/…/SessionStore.kt, core/data/…/repository/AuthRepositoryImpl.kt, LocalDataWiper.kt, SettingsRepositoryImpl.kt.

  • Token in the Keychain, shared access group, accessibility AfterFirstUnlockThisDeviceOnly (background tasks need it while locked; it never leaves the device or enters a backup).
  • States: signed out, signed in (email), expired (email). Expired keeps the library readable and shows "Sign in again to sync".
  • Account marker. Keep the last signed-in email and server outside the Keychain. On sign-in, wipe local data first if the email or server differs, or if data exists with no recorded owner. This is what stops one account's library appearing under another after a restore.
  • Sign-out: server call with a 5 s timeout, then wipe: cancel all work, clear every table inside the sync actor, delete articles, thumbs, pdf-uploads, temporary downloads and exports, checkpoint and vacuum, clear the token. The device id and preferences stay.
  • Delete account (App Review requires it in-app; it exists): dialog where the user types their email, DELETE /v1/account, then the same wipe.
  • Custom server. Must be https; http only for localhost and 127.0.0.1 (add NSAllowsLocalNetworking to App Transport Security for that). No query, fragment or credentials. Changing it while signed in signs out and wipes, so a token is never sent to a different server.
  • Email validation: ^[^\s@]+@[^\s@]+\.[^\s@]+$, at most 254 characters. Strip whitespace from the code before sending.

Telemetry, consent and privacy

D15 in docs/decisions.md is binding for every client. Reference: apps/android/core/domain/…/Telemetry.kt, core/data/…/telemetry/TelemetryDecorators.kt, apps/android/app/src/play/kotlin/app/sroka/telemetry/FirebaseTelemetry.kt.

  • Analytics is off until the user accepts the first-run prompt ("Help improve Sroka?", "Allow" / "No thanks", link to https://sroka.app/privacy). Crash reports are on by default with a switch in Settings.
  • Events, parameters as enums only: screen_view, login {method: email_otp}, save_item {source, kind}, open_item {kind}, archive_item, unarchive_item, favorite_item {on}, delete_item, add_tag, search_used, import_start {source}, export {format}.
  • Never send URLs, domains, titles, search text, tag names, file names, email, user id or the server URL. No user id is set on the SDK.
  • Emit events from decorators around the repositories, as Android does, so views stay free of telemetry calls.
  • No advertising identifier and no tracking, so no App Tracking Transparency prompt. Ship a PrivacyInfo.xcprivacy manifest and fill the App Privacy answers from the same list.
  • Debug builds send nothing.

Testing and CI

Unit (Swift Testing)

  • Core ports against the shared vectors.
  • Op building and coalescing.
  • SyncEngine against a stubbed URLProtocol and an in-memory GRDB queue: push, each rejection reason, aliases, rebase, 410 resync, 401. Android's cases are the checklist (A12).
  • Package installer: every path attack, entry and size limits, SHA mismatch, interrupted swap.
  • Migrations from every released schema; query plans for list sorts.
  • View models with fake repositories, one fake per domain protocol as in apps/android/core/testing.

UI and end to end

  • Snapshot tests of stateless screen content with fixed fixtures, light and dark, iPhone and iPad, large Dynamic Type. Same idea as Android's …Content composables (apps/android/docs/SCREENSHOT_TESTING.md).
  • XCUITest journeys against the local stack: sign in with the OTP read from the wrangler log, save, sync, read offline, archive, search, sign out. scripts/e2e-local.sh shows how the stack is driven.
  • Manual device pass for what the Simulator cannot prove: Share Extension from Safari and other apps, background downloads, low-storage and Low Data Mode behaviour.

CI

  • Build and unit tests per package on every PR; snapshots when UI packages change; journeys nightly.
  • A release preflight like scripts/release-preflight.sh: fail if the archive contains a placeholder Firebase config or is not distribution-signed. Android shipped two releases with a placeholder config before that check existed.

UI design: the Android product, rebuilt from iOS parts

Same screens, words, colours and icon as Android. What changes is the furniture: a floating tab bar instead of chips for destinations, toolbar buttons instead of a floating action button, context menus and sheets instead of bottom sheets and snackbars, all on Liquid Glass. The frames below are drawn in HTML to show layout and intent; build them from system components so the real material, motion and accessibility come for free.

Principles

Content is paper, controls are glass

The list and the article sit on the brand Paper colour edge to edge. Navigation floats above them in glass: tab bar, toolbar buttons, the reader's bottom bar, menus and partial-height sheets. Never put glass on a row, a card or a banner, and never stack glass on glass.

Brand through tint, not chrome

Brand blue is the app tint: selected tab, links, switches, primary buttons. Beak yellow is reserved for reading progress and the favorite star, as on Android. Nothing else gets a custom colour.

System components first

TabView, NavigationStack, List, Form, .searchable, .swipeActions, .contextMenu, .sheet with detents, Menu, ShareLink. Custom views only for the row, the chip row, the toast, the end-of-article card and the theme swatches.

Same words

Every label and message is copied from Android (apps/android/**/res/values/strings.xml) and packages/shared/src/vocab.ts: "My List", "Archive", "Favorites", "Preparing…", "Couldn't save the text", "Partial copy", "Preview only". English only, US spelling.

The Eurasian magpie, Pica pica, lives year-round across most of Europe and northern Asia. It belongs to the crow family and is hard to mistake: black and white plumage, a long tail, and a blue-green sheen on the wings.

Type, shape, motion, accessibility

Type

  • Interface: San Francisco through text styles, so Dynamic Type works everywhere. Row title .headline, two lines; meta .subheadline secondary; section labels .footnote semibold.
  • Brand headings (sign-in, "Start your list", empty states): Outfit 600, bundled from apps/android/core/designsystem/src/main/res/font/outfit.ttf (OFL), scaled with relativeTo:.
  • Article text: New York or San Francisco at 18 px × the user's scale. The reader scale is independent of Dynamic Type, as on Android.

Shape

  • Thumbnails 48 pt with a 9 pt continuous corner; status badge 18 pt on the top-right corner.
  • Banners and cards 16 pt; end-of-article card 22 pt; chips and buttons are capsules.
  • Let sheets, menus, the tab bar and toolbar buttons keep their system shapes so they stay concentric with the screen corners.
  • Row dividers are inset to the text, the iOS convention (Android has none).

Motion and haptics

  • System transitions only: push, zoom from the row into the reader (.navigationTransition(.zoom)), sheet detents.
  • Haptics: selection tick at swipe threshold, success on save, warning on destructive confirm, error on a wrong code.
  • Rows animate in and out of the list on archive and undo.

Accessibility

  • Row reads as one element: title, site, time or progress, status ("Waiting to sync"), then custom actions for Archive, Favorite, Tags.
  • Reduce Transparency and Increase Contrast: system glass falls back to solid; check the toast and end card do too.
  • Reduce Motion: no swipe-peek, no zoom transition.
  • All targets at least 44 pt; the trailing star is decoration, the action is in swipe and the menu.
  • iPad keyboard: ⌘N save, ⌘F search, ⌘R fetch, E archive, S favorite, arrows to move between rows.
